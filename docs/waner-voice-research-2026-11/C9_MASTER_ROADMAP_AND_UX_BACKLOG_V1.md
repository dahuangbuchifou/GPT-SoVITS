# C9 总任务台账与语音工作台优化清单 V1

**更新日期：2026-11-13；状态：分阶段实施，未完成项不得标记通过。**

## 0. 目标与双主线

- **A. Dahuang's Voice Studio（应用侧）**：通过可配置LLM提供文字AI对话，选择声音/引擎，提供TTS、历史音频和可控双向语音交互，未来安全支持远程访问。
- **B. Dahuang's Voice Factory（制作侧）**：声音数据授权与准入→零样本试声→音质审核→版本注册→按需微调→部署与回滚，能处理第二个获授权的声音，**不能依赖复制婉儿专属权重**。
- **C. 生产隔离（横向约束）**：已有GPT-SoVITS生产Gateway/9880/9890、OpenClaw、Cloudflare/Reverse SSH及原Voice Studio V1.4不因实验版开发而自动改变。

完整愿景不止“让婉儿开口聊天”；核心验证还包括可维护、可扩展的**多声音快速生产能力**。

## 2. 严格优先级与逐项完成标准

记号：☐未完成、◐进行/待实机验收、☑已按限定范围确认。每项记录证据与实际日期后才更新。

### P0：稳定可用的双向对话

- [ ] **C9-07a 麦克风权限定位**：站点 `http://127.0.0.1:17861` 的Mic=允许、Windows允许桌面程序访问、选定输入设备、无声学设备故障；记录浏览器和原始Web Speech错误类别（不含音频/私聊内容）。不得靠关闭浏览器安全保护解决。
- [ ] **C9-07b 输入交互验收**：Enter发送、Shift+Enter换行、中文输入法候选确认不误发送；发送只发生一次，空文本被拒绝。
- [ ] **C9-08 可靠STT适配器**：浏览器语音识别可选；通过抽象STT API可替换为用户批准的本地或云识别。只显示转写供确认，不默认自动发往LLM。测试浏览器、语言、麦克风错误、拒绝授权和隐私告知。
- [ ] **C9-08 双向语音最小闭环**：主动录音→确认转写→DeepSeek返回→用户选择婉儿朗读。与`/api/tts`并发上限及RTX3070 8GB生产优先原则相容。
- [ ] **C9-06 补齐逐段体验验收**：观察第一段可在全段完成前播放、分段状态准确、停止后无后续请求；正在执行的上游TTS不强杀。

### P1：Voice Factory核心（避免只优化UI）

- [ ] **C9-09 多声音与模型版本注册实用化**：模型/权重版本、授权状态、参考录音SHA、引擎能力、生命周期、默认模型、回滚规则；未获授权声音不可上线。
- [ ] **C9-10 三层声音制作流水线**：L1授权原声快速试声、L2多参考/试听评估、L3按需审批微调；将C3–C8标准化规则变成可配置模块，避免对每个声音重做技术审计。
- [ ] **C9-11 第二声音试制**：使用一个新获授权声音，验证不复制婉儿权重和代码即可建档、试声、评价、导入Studio；记录耗时/缺陷/资源，证明“可复用”。
- [ ] **C9-12 统一引擎适配**：GPT-SoVITS生产版优先，IndexTTS LoRA150仅受控离线候选；参数与音质不默认等价；严禁生产路径热切换实验模型。

## 3. C9-07麦克风故障的最小排查

当前实验版使用浏览器Web Speech API，报错“麦克风权限被拒绝”尚不等于已证明硬件坏或Windows系统权限关闭：

1. 浏览器打开`http://127.0.0.1:17861`，在地址栏站点权限中确认麦克风允许；若曾拒绝，重设权限并刷新。
2. Windows“设置→隐私和安全性→麦克风”开启麦克风访问及允许桌面应用访问，并检查系统选定录音设备/录音机是否正常。
3. 若仍失败，记录浏览器类型与Web Speech事件原始`error`（如`not-allowed`、`service-not-allowed`、`network`）；不能用模糊的中文提示代替根因。设备许可和语音识别服务许可并不等价。
4. 浏览器语音识别服务可能处理音频数据，需明确隐私告知；后续可用隔离STT适配器替换，而不是要求用户长期使用浏览器内置识别。

## 4. 里程碑与范围纪律

**下一次只做一到两个可复验的小目标：先解决麦克风权限及回车输入；然后做最小“录音→确认文字→AI→语音”闭环。** 这两项稳定后，将开发资源切回多声音注册及第二声音试制。

每次完成后：记录用户实测证据/测试结果→更新本台账状态→经审查归档GitHub。未知项一律标记“未知/未验收”，不能以模拟测试替代实机验证。公开代码、原始录音、使用授权及远程发布分别审批。
