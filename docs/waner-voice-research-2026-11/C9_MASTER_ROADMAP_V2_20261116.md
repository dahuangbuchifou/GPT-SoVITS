# Dahuang's Voice Factory & Voice Studio — 阶段总清单 V2

**状态截至2026-11-16。此文件为当前权威进度总览；原`C9_MASTER_ROADMAP_AND_UX_BACKLOG_V1.md`作为历史技术台账保留。**

## 一、项目目标不变

构建可以持续扩展的声音平台，而不是仅让婉儿完成一次TTS：Voice Factory负责合法声源授权、数据准入、外部训练插件/通用模型入口、参考与权重版本/听评/回滚；Voice Engine负责GPT-SoVITS等不同后端的统一接口、进程/缓存/设备资源隔离；Voice Studio负责可切换声线的文字TTS、可替换LLM对话、历史、播放与未来双向语音/安全远程访问。已稳定的婉儿生产Gateway/9880/9890/OpenClaw、Cloudflare及旧Voice Studio绝不因开发版实验默认变更。

### 身份与权限规则

- `voice_002` 是不可随意重命名的长期内部ID；`dahuang`为显示名。
- `e15_s100` 是首个已验收的**非执行候选**，不能设默认，也不允许直接通过生产9880/9890切换。
- Factory catalog.v1里的研究/disabled模型、私有candidate manifest和Studio registry v1是**三层不同的数据与授权边界**，不能通过直接复制JSON跨层授权。
- 训练/语音素材与权重只存本机获授权目录，不上传Public GitHub；模型、服务、公开网站发布分别审批。

## 三、分优先级任务清单

### P0 当前主线：C9-16M Studio多声音实际接入

- [ ] **M02 — 只读启动与进程隔离审查**：确认`Start_Studio_With_AI.cmd`及关联脚本存在性、17861和9880/9890监听PID/进程父链，识别潜在共用CMD/控制台风险。**完成标准**：新的脱敏快照报告可判断下一步是否要独立启动器；不要求现在重启。进程树不是操作系统级隔离证明。
- [ ] **M03 — dahuang专用TTS适配器**：设计独立进程、私有配置与缓存、SHA锁定模型、CPU/FP32优先的单任务队列；无权访问生产权重切换接口。**完成标准**：无Studio介入时能受控服务一个指定的本地合成请求，完整WAV+耗时+质量门禁，失败不留假成功；真实执行另需授权。
- [ ] **M04 — Studio开发版声音路由**：婉儿走原授权路径，dahuang只走新隔离适配器。保持`candidate`禁用直到单独批准开发版执行；后端强制鉴权，不仅禁用前端按钮。**完成标准**：开发版可以分别选择两声线并合成，互不污染配置/音频/服务，原9880/9890不热切换。
- [ ] **M05 — 多声线回归/失败回退**：至少验证正常短句、长句/切句、明显静音/异常WAV拒绝、单并发任务/取消尚未开始任务、进程崩溃/重启、备份恢复与防重复运行。**完成标准**：婉儿旧路径功能不退化，dahuang新增路径可重复，所有失败有可追踪记录。

**特别约束**：C9-14在CPU下合成一条5.90秒WAV花费约32.67秒，仅说明离线可行；本轮不得承诺dahuang低延迟实时聊天。GPU研究须先独立资源预算、排期与授权，避免RTX3070 8GB生产显存冲突。

### P1 声音工厂做成可重复生产流程

- [ ] **VF-05标准声源准入模板**：获授权录音→WAV质量/环境/单人/文本对齐/参考选片→声音身份与数据集manifest；分别记录ordinary/happy等表达来源，强情绪不默认混训。

- [ ] **VF-07模型版本管理与发布审批**：`research → candidate → approved → dev enabled → production`是治理目标，不强行改旧catalog.v1枚举；版本回滚、异构引擎适配和反悔/撤销使用许可都有清晰路径。
